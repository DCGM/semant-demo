# Reporting feedback about semANT

This guide is for people using semANT in libraries, social sciences, digital
humanities, annotation and related research. You can report a problem, a confusing
workflow, a missing feature or an idea for improvement. **You do not need to
know how the software works or suggest a technical solution.**

## Create a user-feedback issue

[Open a new GitHub issue](https://github.com/DCGM/semant-demo/issues/new).
Begin its title with **`[User draft]`** and briefly describe the problem or
goal, for example: `[User draft] Comparing annotations across documents is difficult`.

You do not need a formal specification. A few sentences are enough to start;
developers can ask follow-up questions. If possible, keep one main topic per
issue.

## What to include

Include **only what is relevant and available**:

- **Your goal:** What were you trying to achieve? For example, find references
  to a person in historical texts, compare search results, or review annotations.
- **What happens now:** What do you see or have to do today? If something seems
  wrong, what did you expect instead?
- **What you would like to change:** Describe the result or workflow that would
  help you. A suggestion is welcome, but you do not need to design the solution.
- **An example:** If possible, link to the page or a shareable document/collection,
  include a search query or annotation example, or describe the steps that led
  to the problem. Mention if the behavior occurs only sometimes.
- **Screenshot or short recording:** Especially helpful for confusing screens,
  missing controls, unexpected results and error messages. Mark or describe
  the relevant part so developers know what to look at.
- **Why it matters:** Say if the issue blocks your work, affects many documents
  or is something you encounter repeatedly.

You can write in everyday language. It is fine not to know the correct name of
a feature. **Do not include passwords, personal information, or restricted
research materials.** If an example cannot be shared publicly, describe it
without revealing private content.

## Example

**Title:** `[User draft] Hard to compare person-name annotations across documents`

> When checking person-name annotations in my collection, I need to compare
> several occurrences and their surrounding text. I have not found an easy way
> to do this without repeatedly opening individual documents. I would like a
> list showing each occurrence with a little context. I can provide an example
> collection or screenshot if useful.

## What happens next?

A developer may ask for clarification, check existing features or issues, and
refine **the same issue** into a development task. If the request is large, they
may link smaller implementation issues while preserving the original report.

You are **not expected** to specify tests, architecture, code changes or other
technical details. Submitting feedback does not mean the change has been
scheduled or approved for implementation.
